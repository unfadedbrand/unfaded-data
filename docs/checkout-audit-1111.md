## Подключение RetailCRM

Подключённый инструмент RetailCRM сначала не ответил, затем вернул ошибку разбора адреса запроса. Причина в исходниках коннектора: RETAILCRM_URL принимает hostname без HTTPS как готовый URL.

По разрешению Леры исправление https://github.com/unfadedbrand/unfaded-retailcrm-connector/pull/1 объединено в main (2231c5db95844f047880f16573e0e8df45ab6e82). В Render подтверждены репозиторий, ветка main и корневая папка retailcrm-connector рабочего сервиса unfaded-retailcrm-connector-1. Автоматическое развёртывание dep-dbk96mivcj2c73fqkas0 завершилось 02.11.2026 в 16:43 МСК со статусом Deploy succeeded | Live. Исправление нормализует hostname в HTTPS и скрывает полный URL запроса при сетевой ошибке. Сборка TypeScript и три теста проходили с вымышленными учётными данными и подменённым fetch.

После развёртывания подключённый rc_reference(dictionary="statuses") успешно получил 43 статуса (success=true). Доступ к API восстановлен. rc_list_integration_modules по-прежнему получает HTTP 404 API method not found на /api/v5/integration-modules: это отдельная ошибка метода, список интеграций не проверен. Права, ключи и переменные окружения не изменялись. Заказы и клиенты не изменялись.

После восстановления подключения остаются сквозные проверки 1/2/3 вещи, промокод/CREDITS, доставка, совпадение сумм Тильда → RetailCRM → АТОЛ. Они не считаются пройденными по результату текущего аудита. Заказ/оплата/фискализация требуют отдельного согласованного тестового сценария.
